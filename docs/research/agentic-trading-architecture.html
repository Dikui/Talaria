READ THE ARCHITECTURE

两个循环，
一个资金边界。

Research freely. Execute deliberately.

这不是把多个 Agent 串起来下单，而是把不确定的推理，接到可验证、可恢复的交易系统上。

01
先看上层：研究如何变成策略

生成、回测、反馈形成研究闭环。只有独立验证与批准后的版本，才能进入在线决策。

02
再看中层：观点如何变成成交

信号经过组合和硬风控，形成持久化订单意图。订单回报进入账本，再对账到实际账户。

03
最后看底座：状态不能混用

研究记忆、工作流状态、资金事实是三类存储。恢复一个工作流，不等于恢复券商事务。

02 / Development Modules

把 16 个逻辑节点，收敛为 9 个开发 Module。

按职责与 Interface 拆分，而不是按 Agent 角色或部署进程拆分。以下是面向 Talaria 的构建建议，不是已实现能力。

8+1业务 Module + 运行控制 Module

起步形态：单仓库、模块化单体。 面向低频研究与交易，先回测、再 paper；不要一开始拆成 9 个微服务。

M01

数据中心

data

接入行情、财报、新闻与交易日历；统一标的和时间，生成决策时点“当时可知”的数据快照。

主要输出EvidenceSnapshot
对应节点 06 · 时点数据视图
M02

策略研究

research

提出研究假设，生成因子与策略代码；调用评测 Module 完成沙箱实验，利用实验反馈和研究记忆迭代候选方案。

主要输出StrategyCandidate
对应节点 01 / 02 / 15
假设 · 代码 · 研究记忆
M03

信号生成

signals

用已发布策略分析数据；支持数值模型、单 Agent 或多角色分析。输出带证据、有效期和弃权状态的观点，而非订单。

主要输出Signal
对应节点 07 · 分析与信号
M04

组合管理

portfolio

合并信号、分配资金、控制相关性与集中度；结合现有仓位和未完成订单，计算净额化的目标仓位。

主要输出PortfolioTarget
对应节点 08 · 组合构建 / 分配
M05

风险控制

risk

用确定性代码强制检查限额、权限、价格、时效和敞口。返回批准或拒绝及明确理由，不依赖 Agent 自觉遵守。

主要输出RiskDecision
对应节点 09 · 确定性风控
M06

订单执行

execution

生成差量订单并维护订单状态机；处理撤改单、部分成交、超时和恢复。通过 adapter 对接模拟器、paper 或券商。

主要输出OrderIntent · ExecutionReport
对应节点 10 + 节点 11 的 adapter
券商本身仍是外部系统
M07

账本与对账

ledger

记录现金、仓位、成交、费用与未完成订单；与券商核对并重建账户状态。保留差异与未决状态，不静默修补事实。

主要输出AccountState
对应节点 12 · 账本与对账
M08

评测验证

evaluation

负责回测运行、独立样本外验证、交易成本、收益归因、基线比较与机制消融。复用交易内核，不另造一套仓位与账本逻辑。

主要输出EvaluationReport
对应节点 03 / 13
以及节点 04 的独立验证
M09

运行控制

runtime

调度流程，管理超时、预算、审批记录、策略版本发布、运行追踪与告警。组织调用，但不接管业务计算或交易权限。

主要输出RunState · PublishedStrategy
对应节点 05 / 14 / 16
以及节点 04 的审批流

节点是架构能力，Module 是开发归属：节点 04 拆为 evaluation 的验证与 runtime 的审批流。研究记忆由 research 管理，signals 可通过只读、时点过滤的 Interface 检索；不得混入资金状态。PublishedStrategy 包含图中的 StrategyVersion 与批准范围。名称均为建议契约，尚非冻结协议。

只维护一个评测入口

research 调用 evaluation，不各自造一套回测引擎。实验执行与结果比较集中在同一个 Module。

只维护一份账户事实投影

portfolio / risk / execution 读取 ledger 提供的账户状态，不各自维护一套持仓真相；通过对账校验外部事实。

编排不吞掉业务职责

runtime 负责组织流程，不负责计算仓位、修改风控限额或解释成交。资金控制在业务 Module 中执行。

01 · Signals 不能直接下单

只能提出观点，不能持有券商交易凭据。数值模型和 Agent 都必须经过组合、硬风控与受控执行出口。

02 · Risk 批准不是永久通行证

实际发送前重新检查最新账户、未完成订单、数据时效和限额；并发订单必须纳入同一份风险预算，不能各自通过后合计超限。

04 / Build in Three Stages

先证明闭环正确，再增加智能程度。

每阶段通过可验证的验收条件后再推进；不是先把所有 Module 做完，再尝试集成。

01不接 LLM

确定性的回测闭环

先用一个简单数值策略，把从历史数据到现金与仓位的整条链路跑通。

历史数据 → 数值策略 → 目标组合 → 风控 → 模拟成交 → 账本 → 基础评测

验收条件 / EXIT CRITERIA

  • 同一数据和配置可以复现结果。
  • 每笔交易能追溯到信号和风控决定。
  • 现金、仓位、费用与成交记录一致。
  • 超限订单被拒绝，不会默默穿透。
涉及 Moduledata / signals / portfolio / risk / execution / ledger / evaluation，以简单 runner 串联。每个首版可以很小，先跑通 Interface。
02PAPER FIRST

Paper + 一个分析 Agent

接入实时数据与 paper adapter，增加一个分析 Agent，并与数值基线比较；补齐持久化、超时查询、重启恢复和对账。

实时数据 + 单 Agent → 原交易内核 → Paper → 故障演练与恢复

验收条件 / EXIT CRITERIA

  • 重启后不盲目重复下单。
  • 未知订单不被直接当作失败，先查询与对账。
  • 账户差异能被发现、告警并阻止不安全推进。
  • Agent 与数值基线在相同数据和成本假设下比较。
重点补齐runtime / execution / ledger 的持久化与恢复；signals 新增 Agent adapter。重点不是短期收益，更不代表已经验证实盘。
03受控发布

自动研究与版本晋升

自动提出假设、生成代码并循环实验；增加独立验证、人工批准、策略版本注册、撤回与回滚。

自动研究 → 独立评测 → 人工批准 → 版本注册 → 受控切换

验收条件 / EXIT CRITERIA

  • 研究候选不能自行批准并上线。
  • 每个已发布版本关联数据、代码、模型、提示词与评测记录。
  • 批准范围可验证，撤回与回滚路径可演练。
  • 有增益证据再加入多 Agent 辩论与长期记忆。
重点建设research / evaluation / runtime。不允许把本轮最优回测结果直接上线；实盘是另一项需要单独验证的能力。

05 / Contract First

优先固定六种对象，再并行开发。

先约定少量稳定 Interface，让数据、模型与券商的复杂度留在各 Module 的 implementation 中。

建议契约 · 字段示意，不是完整 Schema 或已实现协议；AccountState 等模块输出需另行细化。
对象核心内容必须约定的不变量
EvidenceSnapshot当时可知的数据数据快照身份、决策时点、证据引用、可获取时间与来源版本。所有证据在决策时点已可知；明确缺失、陈旧和修订数据的处理规则。
Signal观点，不是订单标的、观点、证据、期限、策略版本与弃权状态。过期或无效信号不得悄悄沿用；模型自报置信度不等于校准后的胜率。
PortfolioTarget目标权重账户、目标权重、约束、资金预算、有效期和参考账户状态版本。目标必须绑定账户与时点；组合计算和发单前检查均考虑未完成订单的敞口。
RiskDecision批准 / 拒绝批准范围、拒绝理由、政策版本、目标身份与校验时点。只对指定目标、账户和期限有效；状态变化后必须重新校验，不得作为通用通行证。
OrderIntent有身份的交易意图稳定唯一身份、账户、标的、方向、数量与价格规则。发送前持久化；同一身份不能代表不同命令。未知提交结果先查询，重试语义由券商能力决定。
ExecutionReport外部订单与成交事实外部订单身份、回报身份、状态、成交明细、费用与事件时间。确认不等于成交；明确重复、乱序、部分成交与费用更正的处理规则，不重复记账。

Interface 不只是字段，也包括调用规则。

必须说明谁可以调用、调用顺序、失败怎么返回、哪些操作允许重试，以及状态过期如何处理。存在真实替换需求时才设置 seam，例如历史 / 实时数据、数值 / Agent 信号、模拟 / paper 执行 adapter；调用方与测试经过同一 Interface。

起步建议：先跑通闭环，不先堆角色。

一个分析 Agent + 一个数值基线，先做 paper。先证明时间数据正确、硬风控有效、未知订单可对账，再增加辩论、记忆和自动研究。

恢复工作流 ≠ 订单恰好执行一次。

发送前持久化意图；提交结果未知时先查询与对账，不盲目重试。券商去重能力与本地恢复语义须单独验证。

不把回测表现当作生产证明。

固定数据、模型、提示词、代码与风险政策版本。检查未来信息泄漏，计入交易与推理成本。本次未复现收益或验证实盘。
