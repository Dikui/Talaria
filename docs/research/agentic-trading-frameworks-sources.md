### 2.2 回测、执行和风控边界

1. **事实：本次源码的 `run_backtest` 是决策质量评估，不是组合交易仿真。** 文件明确写出没有成交数量、成交价和现金账本；每个 `(ticker, date)` 是独立单元，即使传入持仓，也是每个单元使用同一静态组合。输出是方向命中率和 alpha 等评分，不能据此推导策略 NAV、可实现收益或资金容量。[明确边界](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/backtest.py#L1-L15)；[单元循环](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/backtest.py#L143-L203)；[汇总口径](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/backtest.py#L206-L236)。
2. **事实：它做了一部分时间边界处理，但并未实现完整历史信息重放。** 工具从运行状态注入分析日并限制日期范围；Yahoo 对历史分析屏蔽当前快照和没有发布日期的报表；Memory Log 屏蔽尚未成熟的结果。这些改善不能消除所有泄漏：情绪分析员自身说明 StockTwits/Reddit 等近期流未归档，不能形成历史 PIT 数据；回测输出也标注文本源不归档、结果是 indicative 而非 repeatable。[工具日期限制](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/agents/tools.py#L18-L38)；[历史快照屏蔽](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/dataflows/vendors/yahoo/fundamentals.py#L23-L39)；[无日期报表屏蔽](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/dataflows/vendors/yahoo/fundamentals.py#L107-L118)；[社交源限制](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/agents/analysts/sentiment_analyst.py#L1-L17)；[回测披露](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/backtest.py#L89-L125)。
3. **事实：组合经理仍是 LLM 裁决，不是独立确定性交易风控器。** 其代码综合风险讨论并返回决策/评级，主图随后 END；可选 Portfolio 对象提供持仓和现金上下文，不执行订单。已核查路径没有账户余额占用、订单幂等、券商成交确认、硬仓位/杠杆约束或 kill switch 的实现，不能把角色名“Risk/Portfolio Manager”当作这些能力已具备。[组合经理](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/agents/managers/portfolio_manager.py#L23-L104)；[图终点](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/graph/setup.py#L175-L187)；[broker-neutral 持仓输入](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/portfolio.py#L1-L72)。

### 2.3 宣传与代码的差别

- **README 宣称**风险批准后向模拟交易所发单；**所查运行图和回测明确不实现该链路**。因此报告只认定“生成投资评级/提案 + 决策评价”，不认定“完整 simulated exchange”。[README 描述](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/README.md#L102-L106)；[回测反证](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/backtest.py#L9-L15)。
- **论文宣称**多 Agent 在作者实验中优于若干基线；本次没有重跑实验、核对数据集/成本/模型时间污染，不能把论文历史实验移植为此 2026 提交的收益保证。[作者论文](https://arxiv.org/abs/2412.20138v7)。

**架构推断：** 最适合借鉴它的有界状态图、分析员上下文隔离、决策日志和“已成熟结果才可进入记忆”的约束；若目标是真实交易，应在图外另设策略评估、组合优化、硬风控、订单管理与券商适配。这个建议由上述无订单/账本的边界推出，并非项目已实现的能力。

## 3. FinRobot：必须区分论文版与当前桌面实现

### 3.1 版本混称容易导致错误设计判断

**官方 README 的版本定位：** V0 为 AutoGen 教育/论文代码；V1 为股票投研报告 Web 应用；V2 为 PydanticAI/FastAPI/React/Tauri 桌面投研工作台。`pip install finrobot` 被说明为 V0。README 还提到开发中的 V3，但本文不把路线图计入已核实能力；V1 仅核实目录/官方版本说明，以下深查对象是 **V2 加 V0 的对照入口**。[官方版本表及安装说明](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/README.md#L31-L56)。

**V0 代码事实：** `FinRobot` 继承 AutoGen `AssistantAgent`，结合 `UserProxyAgent` 注册工具；还有 RAG 包装。默认代码执行配置出现 `use_docker=False`，不应未经隔离直接运行生成代码。这里能确认的是 AutoGen 对话/工具执行样式，不能把 2024 白皮书的四层概念架构等同于当前桌面执行实现。[V0 Agent 和工具注册](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_autogen/finrobot/agents/workflow.py#L22-L100)；[代理执行与 RAG](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_autogen/finrobot/agents/workflow.py#L125-L208)；[白皮书](https://arxiv.org/abs/2405.14767v2)。

### 3.3 回测、执行和风控边界

1. **事实：有真正调用 BackTrader 的后端，但不等于研究 Agent 已闭环交易。** BacktestConfig/Result 是有类型的接口；适配器用历史价格、Cerebro、初始现金和策略/分析器运行。Lead 暴露的 `run_backtest` 工具跑 SMA crossover，而不是将研究报告评级自动映射成每日仓位/订单。[回测类型](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/backtest/engine.py#L20-L122)；[Cerebro 运行](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/backtest/backtrader_adapter.py#L145-L207)；[Lead 的 SMA 工具](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/orchestrator.py#L440-L483)。
2. **事实：当前适配器主动拒绝非美股；默认零佣金、零滑点。** 源码解释其 US-equity/T+0 假设，没有实现 A/H 股 T+1、涨跌幅、印花税、停牌等市场机制；运行结果附零摩擦警告。因此不能把工具结果当作跨市场可落地收益验证。[市场限制](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/backtest/backtrader_adapter.py#L51-L69)；[零摩擦警告](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/backtest/backtrader_adapter.py#L188-L193)。
3. **事实：代码中存在数值/工件质量闸门，但不能混称为执行风控。** 不合理目标价可被清空并记录 valuation_withheld/warning，同时合同明确保留方向评级；IC memo 的 IRR gate 对文本增加代码生成的 PASS 说明，仍返回叙述结果。这些不是券商前置的硬拒单、仓位上限或损失限额。[工件合同设计](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/artifact/contract.py#L22-L28)；[合同检查实现](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/artifact/contract.py#L91-L170)；[IC IRR 文本 gate](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/pipelines/ic_memo.py#L163-L190)。

### 3.4 宣传与代码的差别

- README 宣称“Lead + 五角色 + Bull/Bear/Judge = 9 agents”；本次实际工厂只创建五个子角色，Lead 另行构造。已检索 Python 源码并阅读调度入口，未找到与其宣称相配的三个辩论 Agent 创建/接线路径。因此**可证的是 Lead + 五角色，不将九 Agent 当已核实实现**；“牛熊论点文本”也不等于“牛熊 Agent”。[README 宣称](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/README.md#L111-L137)；[实际角色工厂](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/agents/factory.py#L16-L40)；[Lead 实例化](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/orchestrator.py#L195-L223)。
- “所有数字确定性计算”“每个输出都有 provenance”“Production”是官方表述；本次可证典型算子、归一化数据合同和工件检查，但没有全覆盖验证，不能将表述扩张成审计通过、生产可靠性或数据正确性保证。[官方定位](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/README.md#L31-L72)；[实际 DCF 算子](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/compute/operators/dcf.py#L48-L170)。

**架构推断：** FinRobot V2 更适合作为“研究工作台/报告平台”的参考：数据合同、确定性算子、步骤失败策略、可版本化工件的价值大于单纯角色数量。交易执行系统需要另建；其现有 SMA 回测工具不能作为 Agent 研究决策已被验证的证据。

### 4.2 最重要的训练/测试区别

**事实：训练有意使用下一日价格差，不可将训练曲线当可交易策略收益。** 环境计算 `future_price - cur_price`；Train 将这个 future record 传给反思，并直接用其符号构造方向（大于零买、否则卖）。这是后见学习/记忆构造路径，不能表述成“Agent 在训练期间预测准确”。[未来价格差](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/environment.py#L70-L110)；[Train 反思与 Test 分支](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/agent.py#L351-L418)；[训练动作使用未来符号](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/agent.py#L460-L462)。

**同时不要夸大为“测试也必然直接读未来”。** Agent step 明确只在 Train 保留该 record，Test 将其置为 None；Test 反思使用历史动量等上下文，测试 Agent 从已训练 checkpoint 加载。可证的是这处分支隔离；训练/测试日期是否重叠、原始文件的真实发布时间、摘要模型是否携带未来知识，本次没有逐数据验证。[分支隔离](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/agent.py#L565-L580)；[Test 使用训练 Agent](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/run.py#L87-L101)。

### 4.3 回测、执行和风控边界

- **事实：是简化持仓/反馈模型，不是资金和撮合账本。** Portfolio 直接 `holding_shares += action["direction"]`，以价格变化和持仓计算反馈；没有在此类中实现现金余额、保证金/借券、资金上限、手续费、滑点或券商订单。持续买卖可能累积净持仓；不能将一次 buy/sell 误读为目标权重 ±100%。[Portfolio 实现](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/portfolio.py#L13-L86)。
- **事实：评价脚本另采用每日动作乘次日对数收益。** 这一口径与 Portfolio 的累积股数反馈不是同一个资金账本。故没有统一执行假设前，不应把脚本累计值与其他框架的收益率/Sharpe 并列排名。[评价收益公式](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/data-pipeline/07-metrics.py#L41-L86)；[持仓反馈](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/portfolio.py#L53-L86)。
- **事实/集成疑点：公开准备脚本不是已验证的即插即用数据接入。** 其末尾生成每日期的 tuple，而运行环境校验的是带命名字段的 dict；同一准备脚本使用 `os` 却未在开头导入。本次没有执行转换，不能保证仓库中的示例脚本直接产生运行入口需要的数据。[脚本导入和使用](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/data-pipeline/04-data_pipeline.py#L1-L61)；[打包格式](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/data-pipeline/04-data_pipeline.py#L150-L156)；[运行校验](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/environment.py#L22-L44)。

**作者宣称与推断：** 作者论文主张分层记忆和性格设计改善交易表现；代码确实包含这些机制，但本次未做记忆消融、模型替换、净成本回测或统计复现，不能确认性能收益来自哪一个组件。架构上可借鉴记忆生命周期与引用 ID 的可追溯性，不宜直接搬用其训练绩效或简化持仓模型作为真实交易评估器。[作者论文](https://arxiv.org/abs/2311.13743v2)；[记忆反馈实现](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/memorydb.py#L220-L299)。

## 5. 面向新系统的设计归纳（推断，不是现有项目承诺）

以下建议从上述已核查路径及其明确缺口推导，不是收益结论：

1. **把“投研结论”和“可执行交易意图”分成两种合同。** TradingAgents 最终是评级，FinRobot 最终是 artifact，FinMem 最终是方向动作；三者语义不同。统一接入时须显式定义时点、标的、方向/目标仓位、置信与证据、失效条件，再单独转换为订单。不能通过 prompt 名称推断已经有 OMS。[TradingAgents 决策类型](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/agents/schemas.py#L221-L260)；[FinRobot artifact 输出](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/orchestrator.py#L37-L63)；[FinMem 动作](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/agent.py#L529-L543)。
2. **采用显式、有界调度，慎用“越多 Agent 越好”。** 有依赖的决策链用状态图/固定 Pipeline，独立取数并发，边界设轮数、超时、预算和失败策略；是否需要辩论应以消融和错误率验证，而非团队拟人化作为证据。[TradingAgents 有界图](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/graph/setup.py#L48-L90)；[FinRobot 顺序与降级](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/pipelines/runner.py#L482-L608)。
3. **将四种“记忆”分开。** 执行 checkpoint、对话审计、研究 artifact 和可成熟验证的决策经验应分仓、分权限和保留策略；不得让回测未来结果混入当时可见的记忆。TradingAgents 的 resolved-as-of 过滤与 FinMem 的 Train/Test 分支值得专门测试。[经验时间过滤](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/memory/log.py#L93-L133)；[Train/Test 数据分支](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/agent.py#L565-L580)；[FinRobot 审计历史](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/routes/chat_sessions.py#L66-L130)。
4. **把确定性风控放在 LLM 外。** LLM 风险讨论、输出 schema、估值合同检查分别只能覆盖论述、格式和工件一致性，不能替代现金/持仓/杠杆/交易时段/异常价格的拒单逻辑、人工批准以及停机机制。尤其不要将“风险 Agent”或 `Guardrails` 类名等同于金融风险控制。[LLM 组合裁决](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/agents/managers/portfolio_manager.py#L23-L104)；[FinRobot 保留方向的合同](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/artifact/contract.py#L22-L28)；[FinMem 输出校验](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/puppy/reflection.py#L96-L138)。
5. **以统一的 point-in-time 数据与事件/账本仿真验证策略。** 至少固化原文发布时间、可用时间、价格调整口径、模型/提示版本、决策延迟、成交规则、费用与滑点，再做多次样本和隔离测试。否则这里的“评级命中率”“SMA 零摩擦 BackTrader 结果”“FinMem 动作收益”并非可直接比较的同一种指标。[TradingAgents 评价限制](https://github.com/TauricResearch/TradingAgents/blob/9fa1196fffbcfd9de5146d2dd2869df84ab99838/tradingagents/backtest.py#L89-L125)；[FinRobot 零摩擦](https://github.com/AI4Finance-Foundation/FinRobot/blob/63e1884a42ea7b729551a5424b4bd6a65af636e0/finrobot_desktop/finrobot/engine/backtest/backtrader_adapter.py#L188-L193)；[FinMem 评价口径](https://github.com/pipiku915/FinMem-LLM-StockTrading/blob/be814aa47970de9bf2fdd6a1d5a60ae5cf361b46/data-pipeline/07-metrics.py#L41-L86)。

## 6. 尚无法核实的事项

- **运行正确性与论文复现：** 没有安装依赖、启动服务、执行测试/回测；三论文所用模型、数据、样本外切分、交易成本、统计显著性和现有提交的对应关系没有重现。
- **生产交易安全：** 没有做券商连通、实盘/模拟账户订单、撤单、成交对账、熔断或攻击测试；对已核查入口之外的插件/第三方整合不作结论。
- **历史信息真实性：** 原始新闻/财报到达时间、供应商修订、退市样本、模型预训练信息污染均未逐条核验。日期参数或代码注释不等于完整 PIT 保证。
- **FinRobot 的声明覆盖率：** 未能在所查构造与运行路径确认 README 的九 Agent；未做全量数值/引用完整性审计；V1/V3 不计入已核实主架构。
- **FinMem 的数据与评分一致性：** 未执行准备脚本到运行环境的端到端转换；未验证候选检索是否严格符合论文排序预期，也未统一动作评价与累积持仓反馈的经济含义。

**结论：** 本次最可靠的用途是提取组件和边界：TradingAgents 的有界多角色决策、FinRobot 的数据合同与确定性投研流水线、FinMem 的分层经验记忆。不能据这些源码或作者收益宣称认定任何一个已经覆盖“可靠数据 → 样本外验证 → 硬风控 → 真实订单执行 → 对账监控”的完整生产交易系统。
