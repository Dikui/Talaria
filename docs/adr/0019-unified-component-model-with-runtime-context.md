# 指标、信号、策略使用统一组件模型，防前视由运行时上下文负责

出策略有四种方式：Python 脚本或 Notebook、agent、图表上写规则、人工判断。以后可能还有别的写法。为了不在框架层把写法限制死，只固定少数核心契约，写法以适配器方式增加。

**固定的核心（改动需要新 ADR）：**

1. **组件接口**：指标（输出数值序列）、信号（输出事件）、策略（输出下单意图）三类，上一类可以引用下一类。每个组件带元数据：输入、参数及取值范围（供寻优使用）、输出类型、版本。
2. **运行时上下文 `ctx`**：组件只能通过 `ctx` 取数据。`ctx` 按当前时刻 `as_of` 截断，只在 K 线收盘后求值；跨周期只能看到大周期最近一根已收盘的柱（照搬 Pine 的非重绘规则）。防前视由运行时负责，不依赖写法。
3. **算子注册表**：指标算子以 `foundation/operators` 的 Decimal 实现为唯一权威（ADR-0010），新算子注册时必须附黄金测试向量。

**可插拔的部分：**

- 写法：先实现 Python 和带版本号的 JSON 规则（只调用已注册算子，可以安全地在常驻服务中运行，用于图表规则、预警、扫描）。以后加文字语法、Pine 风格子集或其他语言时，都编译或适配到同一组件接口。
- Python 的运行位置：
  - 用户自己写的 Python 可以在 Notebook 里直接运行（研究模式），也可以在账户进程里运行。研究模式不隔离，防前视靠 `ctx` 截断和截断式前视审计，不防故意绕过。
  - agent 写的 Python 进入模拟盘前，必须人工批准与代码内容哈希绑定的版本，并在资源受限、无网络、读不到数据目录的子进程中运行，只能经宿主传入的已截断数据取数（ADR-0015）。
  - 任何 Python 都不在常驻服务中运行。
- 展示：图表显示后端算出的组件输出（KLineChart v10 异步 `calc`）。

## 两种求值时机

规则分两类，在规则 Schema 中显式声明：

- **收盘求值**：指标、信号、策略和引用它们的规则，只在 K 线收盘后经 `ctx` 求值，遵守上面的非重绘规则。
- **事件驱动**：预警里的价格触碰（画线、关键位）、买一卖一与资金费率阈值等，在每个行情事件到达时求值。只能比较当前事件的值与常量、画线、关键位或已收盘的组件输出，不能引用进行中的柱算出的指标。

现有只能表达单个条件的 `AlertCondition` 升级为 JSON 规则，原来盘中触发的条件迁移为事件驱动规则，触发时刻和冻结证据保持不变。

## Considered Options

- **用受限 Python 作为规则语言**：RestrictedPython 官方声明它不是沙箱，不能在常驻服务里安全运行用户或 agent 写的代码。否决。
- **采用现成的 Pine 实现**：要么用 float，要么有许可证问题或依赖闭源转换服务，而且会形成第二套算子，违背 ADR-0010。否决。
- **所有规则一律收盘求值**：口径最统一，但盘中穿越后回落的触碰和盘口阈值会漏报，改变现有预警行为。否决。
- **每种写法各有自己的运行时**：最快上手，但防前视规则要在每种写法里重新实现一遍，口径会分叉。否决。
