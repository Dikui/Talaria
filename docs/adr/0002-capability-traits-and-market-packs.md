# 通过通用标的内核与 Capability Traits 市场包实现跨资产扩展

核心底座的所有业务层（数据与盘面感知、策略与协同草案、组合定仓与硬风控、执行状态机、复式账本与复盘归因）禁止编写针对特定市场或资产类别的条件分支（如 `if asset == "crypto_perp"`）。系统采用统一的 `Instrument` 核心规格配合五项可组合能力特征接口（`FeedCapabilityTrait`、`MarginTrait`、`CarryTrait`、`SessionTrait`、`OrderConstraintTrait`），将加密永续合约、美股日内以及未来期权、交割期货或港/A 股的规则与数据源差异封装在独立的 `Market Pack`（Python 市场规则与连接器包 + DSH 领域分析技能包）中注册挂载。

## Considered Options

- **先按单一加密永续写死核心流程，后续支持美股时再重构或分叉仓库**：初期快，但永续合约（7×24、全仓/逐仓保证金、标记价格强平、整点资金费率结算、`post_only`/`reduce_only`、各场所 REST 历史 OI/K 线截断差异）与美股（盘前/盘中/盘后分段时段、IEX/SIP 行情源窗口差异、现券/Reg-T 融资、PDT 限制）在感知、定仓、风控与账本上差异巨大，硬编码会导致后续演进成两套割裂系统。
- **采用传统股票百分比目标权重（`target_weight`）作为全资产统一中间表示**：不适合日内杠杆永续合约——多个标的权重之和无法直接表达止损距离决定的真实亏损风险与强平距离。因此统一改为基于 `Risk Unit (R)` 与明确止损价（`invalidation_price`）的风险预算定仓模型。

## Consequences

- 新增资产类别或交易场所时，核心单向业务层与前端/DSH 基础包无需修改接口，只需新增一对实现标准特征协议的 `Market Pack` 并通过通用契约测试套件。
- 每一笔新建仓或加仓计划（涵盖纯人工、人机协同与智能体三类来源）均必须显式提供逻辑证伪止损价（`invalidation_price`），未提供止损边界的草案在组合定仓前一律拒绝放行。
- **量化策略支持范围因此限定为“单标的、带止损、事件触发的日内/波段择时”**：横截面多因子与目标权重再平衡、配对/统计套利等多腿原子开平、无止损策略（网格、定投、持有型）当前不支持；同一子账户同标的多空对冲由 ADR-0006 禁止。三类扩展（`PortfolioIntent` + `TargetWeightSizer`、`BasketPlan` 回合组、子账户级替代定仓模式）的预留位置见架构规范 §1.3（交易方式由 ADR-0015 的插件组合决定），需要时另立 ADR，不进入首个里程碑。
