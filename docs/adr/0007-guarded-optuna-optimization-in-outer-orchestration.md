# 将防过拟合 Optuna 参数寻优置于外圈编排层并强制前置门禁与三段封存

排除引入任何 `GPL-3.0` 传染性回测寻优源码（如 `Freqtrade / FreqUI`），直接基于宽松许可的 `Optuna`（MIT）在外圈运行与寻优编排层（`orchestration`）构建参数寻优器，由其单向实例化核心五层流水线（感知 → 策略 → 风控 → 模拟执行 → 账本评测）完成每轮试验，策略层自身仅声明有界参数空间 `ParamSpace`。任何寻优任务启动前必须先通过自动化截断防前视审计与递归指标预热漂移审计，并强制绑定不可变数据快照执行“训练集 / 验证集（含 `embargo` 隔离带） / 物理封存样本外盲测集（`Holdout OOS`）”三段切分与全量试验计数留痕。

## Considered Options

- **把 `Optuna` 寻优器直接写在第二层（策略层）内部**：由于评估目标函数（扣除滑点、手续费、资金费率与延迟损耗后的净收益/回撤）必须跑完组合风控、模拟撮合与复式账本，将寻优放在策略层会导致策略层反向依赖下游三层，破坏核心业务流水线的单向无环结构。
- **直接复用 `Freqtrade Hyperopt` 或裸调 `Optuna` 在全区间寻优**：`Freqtrade` 受 `GPL-3.0` 强著佐权约束；而原生 `Optuna` 是对时序因果性一无所知的数学黑盒，若无前置截断一致性门禁、参数邻域平坦度检验与物理封存 `Holdout OOS`，极易在数百轮迭代中精准锁定未来函数漏洞或将历史噪声拟合成实盘失效的孤立尖峰。

## Consequences

- 核心五层保持严格单向依赖，同一套策略、风控与模拟撮合代码在实时影子模拟、单次回放与多进程并发寻优间零修改复用。
- 优化器迭代期间在接口层物理不可见 `Holdout OOS` 数据，且所有失败或被约束淘汰的试验均计入累计 `n_trials` 供统计显著性折扣与人工晋升审阅。
