# 初版以人机共用分析工作台为先，并由确定性关键位引擎产出重要价位

初版不以交易闭环为目标，而是先交付“人机共用的分析工作台”：首个里程碑只实现 `L0` 指标算子与关键位算法、`L1` 数据接入与关键位引擎（首发 `Bybit V5 Linear` 永续），以及 `O2` 纯人工看盘页与价位预警；`L3–L5` 交易闭环推迟到第三个里程碑。重要价位（结构位、时段参考位、成交量位、缺口与整数关口，以及单独标注为估算的清算密集区）一律由 `L1 level_engine` 以确定性纯函数按 `cutoff_ts` 计算，智能体只读取、解读与引用，不生成也不修改系统关键位。同一套分析接口（快照、指标、关键位、临时算子、当前图表视窗、标注、预警草案）同时服务浏览器与智能体工具。技术指标只在 Python 中实现一份：v1 以纯 Python `Decimal` 算子核为唯一权威，`TA-Lib` / `talipp` 仅保留为锁定依赖与未来优化候选（见 ADR-0010），图表与 PTC 消费 Python 输出，不再维护三端独立实现。

## Considered Options

- **按原计划先打通交易闭环（回放 → 风控 → 模拟撮合 → 账本）**：工程上最“完整”，但用户初版最在意的是自动产出指标与重要位置；交易闭环在没有可信分析产物前也缺乏输入，先做会推迟可用价值。
- **由智能体直接识别并画出关键位**：实现最快，但结果不可复现、易产生幻觉价位，且无法纳入时点回放、预警与质量评估；保留智能体标注层，但要求其引用系统 `level_id` 或具体 K 线证据。
- **直接接入第三方技术分析 MCP 或关键位库**：现有 MCP 服务器自行拉取实时行情，绕过冻结快照，人与智能体看到的数据会不一致；`smart-money-concepts` 等库按前后各 N 根 K 线判定摆动点，直接使用会引入前视。改为借鉴算法、自研“确认后可见”版本。
- **Python、前端图表与 PTC 三端各自实现指标并以黄金向量对齐**：维护成本最高且仍有漂移风险；守护进程本就常驻，图表与 PTC 改为消费 Python 结果即可。

## Consequences

- 里程碑调整为：M1 数据接入 + 指标 + 关键位 + `--solo` 看盘 + 价位预警（接口按智能体可调用的形态设计）；M2 接入 DSH 解读、会诊、标注与后台简报；M3 交易闭环（`L3–L5`、回放）；M4 智能体自治与评估、`Optuna` 寻优、美股市场包。
- 摆动类关键位须经 N 根后续 K 线确认后才可见，其 `ts_available` 记为确认时刻，与五重时点纪律一致。
- 新增图表只读图层 `SYSTEM_LEVEL` 与预警类型 `LEVEL_EVENT`（触及、突破、回踩）；关键位质量以“触及后 X 倍 ATR 内出现反应的比例”对比随机价位离线评估，并记录人工采纳/忽略反馈。
- 契约回归中的算子一致性检查收缩为 Python 单端黄金向量测试；图表离开守护进程无法自行计算指标。
- **依赖版本基线（2026-11-19 核实）**：指标底层锁定 `TA-Lib 0.8.3`（C 库 BSD-3-Clause、Python 封装 BSD-2-Clause，Python 3.14 + macOS 14+ arm64 wheel 实测可用）与 `talipp 2.7.0`（MIT）。关键位参考项目 `smart-money-concepts`、`trendln`、`pymarket-structure` 均为 MIT，仅可按洁净室原则借鉴算法；`etnfrank/support_resistance` 无 LICENSE 文件、仅 `setup.py` 声明 `wtfpl` 且已停更，不可复制。
