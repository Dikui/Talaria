# 交易流水线运行在独立的账户进程，账户进程是插件宿主

策略、定仓、风控、成交和记账不在常驻服务（ADR-0014）里运行，而在独立的**账户进程**里运行。一个账户进程承载一个或一组子账户；一个**交易方案**就是一份配置，为每个插槽选定插件。不同交易方式（择时、网格、定投、组合再平衡、agent 自主交易）只换配置和插件，不改框架。

**插槽**：数据入口、策略、定仓、风控、成交、工具。首批默认插件来自原 L2–L5 设计：实时本机 WS / 回测直读 Parquet + 虚拟时钟；Python 策略、JSON 规则、agent 交易计划、`ControllerPatch`；按止损距离定仓（`R`）；原七步风控 + 单一仓位回合不变量；1m K 线模拟成交（六条诚实仿真法则）与盘口加逐笔模拟；agent 工具集。

**固定的底线（改动需要新 ADR）：**

1. 事件顺序与时钟：数据 → 策略 → 定仓与风控 → 成交 → 记账；回测与实时同一时钟语义；组件取数一律经运行时上下文按 `as_of` 截断（ADR-0019）。
2. 开仓、加仓、放宽止损必须经过风控插槽；只减风险的操作（收紧止损、减仓、平仓、撤未成交入场单、切 `REDUCING`/`HALTED`）可直达成交插槽。人工、agent、策略三种来源同样适用。
3. 账本格式统一，每个子账户的账本只有一个写入方（ADR-0006），不同方案的结果可以放在一起对比和复盘。
4. 插件接口带版本号，插件声明兼容的接口版本。

**连接方式**：实时数据经常驻服务的本机 WebSocket 订阅；回测在账户进程内直读 Parquet（ADR-0016）。图表人工下单和 agent 会诊产出的草案由常驻服务转发给对应的账户进程；常驻服务只读账本用于展示。回测与模拟盘是同一个账户进程，只换数据入口；`replay_runner` 与 `study_optimizer`（ADR-0007）以批量启动账户进程的方式实现。

**agent 生成的代码**：agent 默认产出交易计划、JSON 规则或参数补丁，都经过风控插槽。agent 写的 Python 策略可以自由回测；进入模拟盘前需要人工批准，并在资源受限的独立进程中运行。

## 对已有 ADR 的修订

- ADR-0006 的“单一仓位回合不变量”与 ADR-0002 的“按 `R` 与止损价定仓”从框架硬约束降为**默认风控与定仓插件的规则**；按写者分库保留为底线 3。
- ADR-0003 的 `Execution Seam` 成为成交插槽的接口，模拟优先不变。

## Considered Options

- **策略放进常驻服务**（Nautilus、LEAN 的做法）：延迟最低，但策略（尤其 agent 生成的）卡死或崩溃会拖垮行情服务和图表。实测本机 WS 只多约 1–2 ms（p99），相对交易所网络延迟和分钟级策略可以忽略。否决。
- **混合模式（可信策略进程内、其余独立进程）**：省下约 1 ms，却要维护两种运行方式。否决。
- **保留原 L1→L5 单向分层作为固定流水线**：只支持“有止损的单标的择时”，网格、定投、目标权重等交易方式都要改框架。否决；分层设计改为默认插件保留。
