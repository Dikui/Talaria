# 冷库在每根 K 线收盘后持续写入，取代快照冻结触发

ADR-0011 让冷库只在快照冻结时发布，前提是 v1 没有独立的实时采集循环、也没有人在快照之外取数。ADR-0014 引入了常驻服务，ADR-0016 让 SDK 直读 Parquet，这个前提不再成立：没有人创建快照时冷库就不更新，策略和 Notebook 读到的历史会落后。

决定：常驻服务在每根 K 线收盘（`confirmed`）后把它写入该分区的尾部小文件；定期把尾部文件合并进分区文件，并在 `data_manifest.sqlite` 中用短事务原子切换清单；被替换的旧文件延迟删除，保证正在读旧清单的读者不受影响。服务仍是冷库的唯一写者（ADR-0006）。快照保留，只用于固定 agent 会诊和预警触发时的证据。

保留 ADR-0011 的约束：同一时间戳后出现者胜；冷库写入失败只记 warning，不阻塞行情和图表；读者只读清单显式列出的文件。

## Considered Options

- **保持快照触发**：冷库延迟取决于有没有人看盘，SDK 直读拿不到最近数据，补尾范围不可控。否决。
- **每根 K 线直接改写分区文件**：Parquet 不支持追加，每分钟重写整月文件成本随历史增长，还会和读者争用同一文件。否决。

## Consequences

- 已发布时间戳的迟到修订按 `revision` 追加到尾部文件，合并时后出现者胜；不再需要 ADR-0011 说的“放宽游标”。
- 待实测：服务补尾与 SDK 直读在并发读写下的一致性。
