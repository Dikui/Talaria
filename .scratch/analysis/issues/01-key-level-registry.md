# 01 — 关键位注册表取代路由里的广播器缓存

**What to build:** 关键位预警不再依赖前端创建快照：任何来源（路由、扫描、预警）的快照冻结都把带 `cutoff_ts` 的 `KeyLevelSet` 版本写入服务内的关键位注册表；服务启动时为需要的标的预热一版；预警按事件时刻取当时的版本，图表取最新版本。

**Blocked by:** None — can start immediately.

**Source of truth:** `docs/architecture.md` §5.4。

**Status:** ready-for-agent

- [ ] `POST /api/snapshots` 路由不再承担关键位的业务写入；搜索广播器上的关键位缓存读写无残留，WS 投影行为保持不变。
- [ ] 服务启动时为有活跃关键位预警或实时订阅的 `(instrument, timeframe)` 按当前时刻从冷库算一版预热。
- [ ] 预警读取 `cutoff_ts <= 事件时刻` 的最新版本；图表读最新版本。
- [ ] 测试：没有前端连接时，由扫描触发的快照冻结后，关键位预警能按 `level_id` 触发；重启后只开关键位预警、关闭扫描，预警仍能触发；后冻结的快照里某价位已 `BROKEN`，更早时刻的事件仍按当时的 `ACTIVE` 状态判断。
- [ ] 现有关键位预警与图表投影测试保持通过。

## Comments

### 实现记录（2026-11-22）

- HTTP、扫描和预警统一通过工作台快照入口冻结证据，每个周期计算并登记一份 `KeyLevelSet`。预警以事件截止时刻选版，图表订阅时重放最大 `cutoff_ts`，并接收该版本的更新。相同截止时刻按登记顺序取后一版。补冻历史时保留旧版本供预警查询。
- 启动以同一时刻预热已武装或冷却中的关键位预警及已分配实时订阅的标的和周期。使用冷库只读连接，冷库写入关闭时仍可读取已归档的柱。预热产生可从快照接口读取的证据，首批实时行情在预热后进入引擎。空冷库跳过对应版本，读取失败记录日志。冷库目前只存 K 线，估算清算位需要后续冻结提供持仓量样本。
- 指定文档与任务单未发现冲突。预警按自身周期分配实时订阅归 `data-access/06`，本单按预警记录的周期预热，重启触发用例使用当前调度器支持的 `1m`。
- 扫描触发和重启触发测试先复现未产生预警，再验证通过。延迟事件测试验证同一 `level_id` 在较早快照为 `ACTIVE`、较晚快照为 `BROKEN` 时的选版。图表测试验证连接后推送及补冻旧快照后的订阅重放。

### 审查修复（2026-11-22）

- 已收盘柱按开盘时刻加周期选取版本，迟到或修订柱的 `ts_available` 不改变选版时刻。盘中更新按本次行情的接收时刻选版，形成中的柱不进入快照取数。每个事件在逐条求值前选版一次，期间冻结的新快照供后续事件使用。
- 冷库写入开启时，启动预热遇到空冷库会在对应标的和周期的历史回填完成后重试一次。冷库写入关闭时，预热直接走正常的快照取数，已有冷库仍可读取。预热、扫描和收盘后冻结共用快照构建与关键位计算，包含按截止时刻取数的持仓量等衍生品输入。
- 有 `ARMED` 或 `COOLDOWN` 关键位预警的标的和周期，每根已收盘柱进入热端后排队冻结。构建与计算在线程中执行，登记回到服务事件循环。冻结截止时刻取收盘时刻与柱可获取时刻中的较晚者。
- 图表接受同标的、同周期的推送，按 `cutoff_ts` 单调更新。相同截止时刻接受服务端替换推送，晚到的 REST 响应保留当前版本。采纳使用当前显示关键位所属的快照。
- 版本的 `cutoff_ts` 晚于 `settings.now_ms()` 时，证据快照仍可按 ID 读取，当前服务的注册表和 WS 投影跳过该版本。每个标的和周期最多保留最近 256 个不同截止时刻，同一时刻以后登记的一版为准。事件早于内存中最早版本时返回空并记 debug 日志。

#### 剩余限制

- 本次事件求值完成后，后台冻结才会登记。新状态从后续事件开始可用，回填完成前的事件也不重放。空冷库且无历史回填的运行模式须等后续快照或收盘冻结补齐版本。
- 内存上限针对注册表，证据快照仍落盘。预警订阅周期的调度仍由 `data-access/06` 处理。清算密集区依赖可取得的时点持仓量输入，当前冷库归档仍只包含 K 线。
